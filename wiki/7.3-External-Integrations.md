# External Integrations

SAGE coordinates six external systems into a single governed workflow. Integration details are configured in `.cursor/mcp.json` and `workflow-config.json`. This page covers each system's role, connection method, and operational status.

> [**DIAGRAM PLACEHOLDER — Integration Map**]
>
> A hub-and-spoke diagram with Cursor IDE at the centre. Six spokes connect to: GitHub (code hosting, branch protection, PRs), Linear (issue tracking, state machines, webhooks), Notion (optional metrics dashboard), Microsoft 365 (Teams transcript retrieval), Azure DevOps (CI/CD pipelines, human QA test plans), and the Profitability Codebase (read/write by agents and hooks). Each spoke is labelled with its MCP connection method where applicable. Mark the Linear webhook spoke and the Notion metrics dashboard spoke with warning indicators for known gaps.

## Cursor IDE

| | |
|---|---|
| **Role** | Executes AI [agents](6.3-Agent-Catalogue), runs [hook scripts](6.2-Enforcement-Reference), enforces the workflow |
| **Integration** | Native — agents and hooks are defined within the repository |
| **Configuration** | `.cursor/agents/*.md`, `.cursor/hooks/hooks.json`, `.cursor/hooks/scripts/*.py` |
| **Credentials** | None (local execution) |

Cursor is the execution environment. [Agents](6.3-Agent-Catalogue) are loaded from `.cursor/agents/` when invoked. [Hooks](6.2-Enforcement-Reference) are registered in `.cursor/hooks/hooks.json` and fire on defined events. No separate integration is required — this is the native environment.

## GitHub

| | |
|---|---|
| **Role** | Code hosting, branch protection, pull requests |
| **Integration** | Git operations (clone, push, PR) · ADO CI/CD pipelines trigger on GitHub PRs |
| **Configuration** | Repository settings (branch protection on `main`) |
| **Credentials** | Git SSH key or HTTPS token (standard developer setup) |

GitHub hosts the Profitability codebase. [Phase-splitter](6.4-Skill-Catalogue) creates per-phase branches and [worktrees](1.3-Glossary) during kick-off. Pull requests follow the merge order defined in the [session manifest](6.1-Session-Manifest-Reference).

ADO CI/CD pipelines fire on GitHub PRs via three pipeline definitions:
- `profitability-db.yml`
- `profitability-api.yml`
- `profitability-web.yml`

SAGE does not replace GitHub or ADO CI/CD. The [completion-report-stop-gate](6.2-Enforcement-Reference) checks SAGE's own S7 test results, not ADO pipeline status.

## Microsoft 365 MCP

| | |
|---|---|
| **Role** | Teams meeting transcript retrieval |
| **URL** | `https://microsoft365.mcp.claude.com/mcp` |
| **Auth** | `M365_ACCESS_TOKEN` environment variable |
| **Configuration** | `.cursor/mcp.json` |

### Used by

| Component | Purpose |
|---|---|
| [kickoff-dev-review](6.4-Skill-Catalogue) | Retrieves Teams meeting transcript from kick-off recording |

**Token expiry:** The `M365_ACCESS_TOKEN` is an OAuth token from the Microsoft identity platform. It expires. If expired, [kickoff-dev-review](6.4-Skill-Catalogue) cannot fetch the transcript and will fail at the transcript retrieval step. The token must be refreshed or replaced with a long-lived service account token.

## Azure DevOps

| | |
|---|---|
| **Role** | CI/CD pipelines, human QA test plans |
| **Integration** | ADO pipelines trigger on GitHub PRs · ADO work item tracking being replaced by Linear |
| **Configuration** | YAML pipeline files at repo root |
| **Credentials** | ADO service connection (existing infrastructure) |

### CI/CD

ADO CI/CD pipelines remain in ADO. The three YAML pipeline files reference GitHub as the source. SAGE does not replace or modify ADO CI/CD.

### Work item tracking transition

ADO work item tracking is being replaced by Linear. The transition is a clean cut:
- Active ADO features complete in ADO
- New features enter Linear
- No dual-tracking for individual features

### Human QA test plans

ADO hosts human QA test plans that are **complementary** to SAGE S7 agent testing. The [sage-s7-ado-handoff](6.3-Agent-Catalogue) reference document defines the relationship:

- SAGE S7 produces `phase-{N}-test-results.md` with `STATUS: PASS`
- ADO human QA runs are stakeholder-facing evidence
- Neither substitutes for the other — both must be satisfied for full closure where the process requires them
- ADO test plan updates follow the handoff checklist **after** S7 reaches `STATUS: PASS`
