# What SAGE Is

SAGE (Semi-Autonomous Guided Execution) is a structural enforcement system for AI-assisted software delivery. It governs how the Profitability team builds features — from requirements through to production-ready code — by defining a fixed sequence of steps and mechanically blocking progression when the conditions for advancement have not been met.

The distinction matters: SAGE is not a recommended process. It is an enforced one. AI agents perform the majority of execution work — interviewing developers, producing plans, writing code, reviewing it, testing it — but they operate within constraints that are evaluated by automated hook scripts at every step boundary. An agent cannot skip a step, declare work complete without evidence, or instruct its way past a gate. The gate checks a condition in the real world — a file exists, a status is set, a score meets a threshold — and blocks until that condition is satisfied.

## The four layers

SAGE operates across four layers. Each serves a different purpose, and they interact in a specific order.

| Layer | Purpose | How it works |
|---|---|---|
| **Execution structure** | Defines what work happens in what order | Four [workflow modes](2.2-Workflow-Modes) suited to different team configurations. Within each mode, a feature is broken into *phases*, and each phase progresses through eight *steps* (S1–S8) in strict sequence. |
| **Enforcement** | Prevents steps from being skipped or completed without evidence | Twelve Python [hook scripts](6.2-Enforcement-Reference) intercept tool calls and agent actions inside Cursor IDE. Each hook checks a specific condition — an artifact exists, a flag is set, a score is zero — and blocks the action if the condition is not met. |
| **SAGE Hone** | Improves the system based on evidence from real sessions | After every completed work cycle, the [session performance evaluator](5.1-SAGE-Hone-Session-Performance) scores agent behaviour. Every five cycles, the [skill effectiveness evaluator](5.2-SAGE-Hone-Skill-Improvement) analyses patterns and proposes targeted improvements to AI instructions — staged for human approval before being applied. |
| **SAGE Intel** | Replaces estimation with empirical delivery data | The [intel recorder](5.3-SAGE-Intel) collects metrics from every completed cycle. The [intel advisor](5.3-SAGE-Intel) answers planning questions — sprint scope, release dates, capacity — using that empirical dataset, calibrated per workflow mode. No human estimation is used at any stage. |

## What enforcement means in practice

Every transition in the workflow has a defined condition. Some conditions are evaluated automatically — a hook script reads an artifact file and checks whether it contains the required content. Others require a deliberate human action — a developer reviews a validation mockup and manually sets a confirmation flag in the session manifest.

A reader who does not understand which type of gate applies at which point will not be able to use the framework correctly. Throughout this wiki, three types of callout distinguish responsibilities:

> **🔵 HUMAN ACTION** — A specific action a human must take. Named by tool, mode, and exact interaction.

> **🤖 AGENT ACTION** — What the AI agent or automated component does without human involvement.

> **🔒 ENFORCEMENT POINT** — A gate enforced by a hook script. Names the mechanism, states what it evaluates, and describes what happens on failure.

These callouts appear in every process page at the point where the relevant moment occurs. They are not decorative — they are the primary mechanism by which a reader tracks who is responsible for what.

## What SAGE connects

SAGE coordinates several external tools into a single governed system:

| Tool | Role in SAGE | Integration |
|---|---|---|
| **Cursor IDE** | Executes AI agents, runs hook scripts, enforces the workflow | Agents and hooks are defined in `agents/` and `hooks/` within the repository |
| **GitHub** | Hosts the codebase, manages parallel development branches, houses pull requests | Phase branches and worktrees are created during kick-off; PRs follow the merge order from the session manifest |
| **Linear** | Tracks feature and phase approval state, manages skill update approvals, triggers automated transitions | Feature issues, phase issues, skill-update issues, and violation issues each follow defined state machines |
| **Notion** | Hosts optional metrics dashboards for leadership reporting | Metrics published by `intel-recorder` when configured |
| **Microsoft Teams** | Captures transcripts from structured kick-off sessions | The `kickoff-dev-review` skill retrieves transcripts via the Microsoft 365 MCP |
| **Azure DevOps** | Runs CI/CD pipelines; hosts human QA test plans | ADO pipelines trigger on GitHub PRs as before; SAGE does not replace ADO CI/CD |

Not all integrations are fully operational. The [Environment Setup](7.1-Environment-Setup) page documents what is in place and what is blocked.

## Key concepts defined

These terms appear throughout the wiki. Each is defined in detail where it first appears in context and compiled in the [Glossary](1.3-Glossary).

| Term | Definition |
|---|---|
| **Session** | A single feature delivery cycle from kick-off through to merged code. Tracked by a session manifest. |
| **Phase** | A unit of work within a session, scoped to a specific set of files. Phases may run in parallel (Sprint mode) or sequentially. |
| **Step** | One of eight sequential activities within a phase (S1 Developer Interview through S8 Completion Report). |
| **Gate** | A condition that must be satisfied before the next step can begin. Enforced by a hook script, not by instruction. |
| **Hook** | A Python script registered in `hooks.json` that intercepts Cursor tool calls and evaluates a gate condition. |
| **Manifest** | The session manifest (`session-manifest.md`) — a machine-readable JSON document that is the single source of truth for session state. |
| **Artifact** | A file produced by a step (e.g., `phase-1-implementation-plan.md`). The next step's gate checks for the prior step's artifact. |
| **Telemetry** | Structured event records written automatically by the `telemetry-logger` hook. Feeds SAGE Hone and SAGE Intel. |
