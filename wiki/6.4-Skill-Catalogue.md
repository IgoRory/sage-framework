*This page is the compact reference for all skills in the SAGE framework — interactive, human-facing capabilities used during kick-off, PRD creation, and continuous improvement cycles. It serves all teams as a quick-lookup resource.*

---

# Skill Catalogue

[Skills](1.3-Glossary) are interactive capabilities defined in `.cursor/skills/[skill-name]/SKILL.md`. They are distinct from [agents](6.3-Agent-Catalogue): skills are human-facing, invoked explicitly by a team member (or on a defined cadence), and typically run during kick-off, PRD creation, or evaluation cycles. Agents are autonomous build-phase executors that run within the S1–S8 step sequence.

## Skills vs agents

| | Skills | Agents |
|---|---|---|
| **Interaction** | Human-facing, conversational | Autonomous, tool-driven |
| **Invocation** | Explicit by team member or on cadence | Loaded automatically at step boundaries |
| **Typical phase** | Kick-off, PRD creation, evaluation | Build (S1–S8), post-merge |
| **Defined in** | `.cursor/skills/[name]/SKILL.md` | `.cursor/agents/[name].md` |
| **Examples** | prd-interviewer, phase-splitter | dev-interview, code-reviewer |

## Skill details

### prd-interviewer

Conducts a structured interview with the Product Manager to produce a complete PRD draft and component specification. Starts from a Linear feature issue or ADO work item. Enforces repo preflight (correct branch, up-to-date with remote). Interviews across six sections with phase-mapped [telemetry](6.5-Telemetry-Reference). See [PRD Creation](3.1-PRD-Creation).

### prd-completeness-check

Scores a PRD across [six dimensions](3.1-PRD-Creation) (100 total). Threshold is 80/100, read from `workflow-config.json`. On pass: sets Linear feature issue to `Ready`. On fail: produces remediation report. The threshold is auto-calibrated by the [skill-effectiveness-evaluator](5.2-SAGE-Hone-Skill-Improvement) over time.

### kickoff-dev-review

Processes a Teams meeting transcript from the kick-off session. Reads the transcript alongside the PRD and component specification from `.sage/prds/[FEATURE_ID]/`. Identifies and categorises developer concerns. Asks follow-up questions for unresolved items. Updates the PRD and produces a dev review log and [phase-splitter](#phase-splitter) briefing note. Runs during Sprint kick-off Step 1. See [Sprint Kick-off](3.2-Sprint-Kickoff).

### phase-splitter

Analyses the PRD and Profitability codebase to generate a recommended phase breakdown using a three-level planning funnel. L1 produces a domain map with verified dependency classification (`verified-in-code / inferred / assumption`) and a shared mutable state audit before any phase cuts are proposed. L2 applies splitting rules, scores each phase for independence (0–100), and adds a three-dimension confidence score (dependency confidence, effort confidence, objective clarity) with an overall recommendation (PROCEED / REVIEW BEFORE BUILD / SPLIT RECOMMENDED / SPIKE RECOMMENDED). L3 generates the session manifest, Linear issues, and worktrees on team confirmation. Supports back-revision (L2 or L3 findings can patch prior level decisions without a full re-run) and deferral (decisions with named unblocking conditions carry forward explicitly). Runs during kick-off Step 2. See [Sprint Kick-off](3.2-Sprint-Kickoff).

### dev-plan

Opt-in replacement for the dev-interview (S1) Q&A interview. Instead of asking the developer questions blind, the agent investigates the codebase first and publishes its findings as a structured, layered plan for the developer to review and correct. Uses a three-level funnel: L1 strategic (work groupings, verified challenges with confidence classification, risks, simplification opportunities), L2 tactical (approach decisions per grouping, test strategy, scenario assessments), L3 execution (final S1 artifact, refined TDD scenarios, open deferrals). Supports back-revision and deferral with named conditions. Only verified (`verified-in-code`) findings drive planning decisions — `assumption`-confidence items are listed separately. Invoked by saying "use dev-plan" at the start of a phase.

### session-performance-evaluator

Evaluates agent execution quality after every work cycle. Scores across [five dimensions](5.1-SAGE-Hone-Session-Performance). Creates Linear violation issues for systematic gate violations. See [Session Performance](5.1-SAGE-Hone-Session-Performance).

### skill-effectiveness-evaluator

Analyses skill performance across 5 work cycles. Proposes targeted SKILL.md improvements. Stages diffs for human approval via Linear. See [Skill Improvement](5.2-SAGE-Hone-Skill-Improvement).

### prd-interviewer-effectiveness-evaluator

Specialised evaluator for prd-interviewer. Uses PRD interview [telemetry](6.5-Telemetry-Reference) and optional traceability-review artifacts. Same governance as skill-effectiveness-evaluator. See [Skill Improvement](5.2-SAGE-Hone-Skill-Improvement).

### intel-recorder

Collects and stores delivery metrics after every cycle. Writes `.sage/intel/velocity-history.jsonl`, regenerates per-mode calibration datasets, optionally updates Notion. See [Intel](5.3-SAGE-Intel).

### intel-advisor

Answers planning questions using empirical data. Three query modes: weekly planning, release date estimation, scope change analysis. See [Intel](5.3-SAGE-Intel).
