*This page is the compact reference for all agents in the SAGE framework — their models, access levels, active periods, outputs, and key constraints. It serves all teams as a quick-lookup resource.*

# Agent Catalogue

[Agents](1.3-Glossary) are AI executors defined in `.cursor/agents/[agent-name].md`. Each operates within the constraints defined in [AGENTS.md](1.3-Glossary) and enforced by the [hook layer](6.2-Enforcement-Reference). An agent cannot exceed its defined scope through instruction alone.

## Agent details

### orchestrator

Primary coordination agent for all [workflow modes](1.3-Glossary). In Sprint mode: manages kick-off, generates TDD specs per phase lane, monitors Foundation merges, triggers post-merge regression, coordinates Review & Merge. In Mob mode: opens Phase Chats at transitions and manages progression. Does not write implementation code. Cannot set `validationConfirmed = true`.

### sprint-coordinator

Monitors Sprint Build Phase in real time. Reads the [session manifest](6.1-Session-Manifest-Reference) and per-lane [telemetry](6.5-Telemetry-Reference). Reports lane status, bottlenecks, and merge sequencing on demand. Strictly read-only. Never initiates a status report unprompted. Does not operate in Mob, Pair, or Solo modes.

### dev-interview

Runs S1. Asks targeted technical questions scoped to the current phase. Validates and refines TDD spec scenarios. Must ask the developer to choose [Autonomous or Checkpoint](1.3-Glossary) build mode before closing. The [plan-mode-enforcer](6.2-Enforcement-Reference) hook blocks all file writes during S1.

### implementation-planner

Runs S2. Maps every TDD scenario to a specific test file and assertion method. Lists all files to create or modify with exact paths. Populates Linear issue tasks. In Checkpoint mode, writes batch definitions to the manifest. Every TDD scenario must be mapped — no unmapped scenarios.

### traceability-reviewer

Runs S3. Bidirectional check between PRD and implementation plan. Classifies findings as Blocker, Major, or Minor. Must write `Blocker findings: N` in exact format — the [manifest-step-gate](6.2-Enforcement-Reference) reads this string. Strictly read-only.

### plan-preview-generator

Runs S4. Produces plan preview artifacts for PM confirmation — canvas (`.canvas.tsx`) for spatial/stateful content, structured Markdown for linear content, or calculation proof for calculation phases. Cannot set `validationConfirmed = true` — must instruct the developer to set it manually. See [S4 — Plan Validation](4.4-S4-Plan-Validation).

### code-simplifier

Runs after each completed S5 task. Applies simplification changes directly — not a suggestion agent. Reverts immediately if any test fails. Never touches test files. Never modifies calculation sequences or financial logic (FTP, allocation). Only touches files in the current phase's `scopedFiles` that were edited in the current task.

### code-reviewer

Runs S6. Reviews code across five dimensions: code quality, security, performance, edge case handling, error handling. Must write `Critical findings: N` in exact format — the [code-review-gate](6.2-Enforcement-Reference) reads this string. Strictly read-only.

### test-runner

Runs during S5 (TDD RGR cycle) and S7 (full test suite). During S5: writes `phase-{N}-tdd-results.md`. During S7: runs regression, signals gap-analyzer, waits for results, compiles final test results into `phase-{N}-test-results.md`. Must write `STATUS: PASS` or `STATUS: FAIL` on its own line.

### gap-analyzer

Runs during S7 alongside test-runner. Generates additional test scenarios not covered by TDD spec (integration paths, UI state transitions, data volume edge cases, permission boundaries). Appends results to `phase-{N}-test-results.md` — never overwrites test-runner output.

### feature-doc-generator

Runs during Phase 04. Generates technical wiki and user guide from all session artifacts. Writes `technical-wiki.md` and `user-guide.md` to `.sage/prds/[FEATURE_ID]/feature-docs/`. Documents what was built, not what was planned.

### session-performance-evaluator

[SAGE Hone](1.3-Glossary). Scores the cycle across [five dimensions](5.1-SAGE-Hone-Session-Performance). Creates Linear violation issues for systematic gate violations (same gate, same agent, >2 times). Never modifies telemetry, manifests, or skill files.

### skill-effectiveness-evaluator

[SAGE Hone](1.3-Glossary). Analyses patterns across 5 work cycles. Stages diffs in `.skill-update-staging/`. Creates Linear `skill-update` issues. Cannot apply its own staged diffs — requires human approval. See [Skill Improvement](5.2-SAGE-Hone-Skill-Improvement).

### prd-interviewer-effectiveness-evaluator

[SAGE Hone](1.3-Glossary). Specialised evaluator for [prd-interviewer](6.4-Skill-Catalogue). Uses PRD telemetry from `.sage/prd-interview-telemetry.jsonl`. Same governance as skill-effectiveness-evaluator. When deployed, the general evaluator must skip prd-interviewer.

### intel-recorder

[SAGE Intel](1.3-Glossary). Collects delivery metrics after every cycle. Writes `.sage/intel/velocity-history.jsonl`, `.sage/intel/release-history.jsonl`, regenerates per-mode calibration datasets. Optionally updates Notion metrics dashboard. Never mixes mode data. See [Intel](5.3-SAGE-Intel).

### intel-advisor

[SAGE Intel](1.3-Glossary). Answers planning questions using empirical data. Three query modes: weekly planning, release date estimation, scope change analysis. Never asks for human estimates — flags low confidence and uses heuristics. Read-only.

### sage-s7-ado-handoff

Reference document defining how SAGE S7 agent testing relates to Azure DevOps test plans. Mapping and checklist only — not an automation agent. ADO test runs are complementary to S7; neither substitutes for the other.
