# S4 — Plan Validation

S4 produces a tangible artifact the developer can see and evaluate before committing to the build. The [plan-preview-generator](1.3-Glossary) agent classifies the phase as UI, Calculation, or Hybrid, then generates the appropriate preview artifact.

---

## Phase classification and artifact type

| Phase type | Artifact | Contents |
|---|---|---|
| **UI** | `phase-{N}-plan-preview.canvas.tsx` | Canvas preview showing layout, components, field labels, editable vs read-only indicators, all component states (default, loading, error, empty, populated). Canvas files must only import from `cursor/canvas` — no npm packages, no relative imports, no network calls. |
| **Calculation** | `phase-{N}-calculation-proof.md` | Calculation proof showing the formula, intermediate calculation steps, and expected outputs with realistic Profitability domain numbers (FTP rates, balance ranges, cost pool allocation percentages). |
| **Hybrid** | Both files, cross-referenced | Canvas preview and calculation proof generated together, with cross-references between the calculated values and the UI fields that display them. |

> **🤖 AGENT ACTION** — The plan-preview-generator reads the implementation plan, TDD spec, PRD, and component specification. It classifies the phase, generates the appropriate artifact(s), and writes them to the phase directory. After writing the artifact, it explicitly instructs the developer on how to confirm.

---

## The human confirmation gate

This is the second of three human-action points in the build sequence. The agent produces the artifact but cannot approve it. Only the developer can confirm that the plan is correct.

> **🔵 HUMAN ACTION** — Review the validation artifact. Open the canvas preview or review the calculation proof directly. Verify that:
> - UI layout matches your expectations from the interview
> - Field editability (read-only vs editable) is correct
> - All component states are represented
> - Calculation formulas produce correct results with the sample numbers
> - Nothing is missing from the phase scope

After reviewing, confirm by editing the session manifest:

1. Open `.sage/sessions/[session-id]/session-manifest.md`
2. Find the JSON block
3. Locate `phases[N].runtime.validationConfirmed`
4. Change `false` to `true`
5. Save the file

> **🔒 ENFORCEMENT POINT** — `validation-confirmed-gate` blocks ALL S5 build tool calls until `phases[N].runtime.validationConfirmed === true` in the session manifest. No agent, hook, or workaround can set this flag — it requires the developer to physically edit the manifest file.

---

## What the agent cannot do

The plan-preview-generator agent cannot set `validationConfirmed` in the session manifest. This is a structural constraint defined in the [agent catalogue](AGENTS.md), not a behavioural suggestion. The [session rules](1.3-Glossary) state: "validationConfirmed and batch.confirmed cannot be set by you."

If the developer identifies issues in the validation artifact, they tell the agent what to fix. The agent regenerates the artifact. The developer reviews again. This cycle repeats until the developer is satisfied and sets the flag.

---

## Enforcement

> **🔒 ENFORCEMENT POINT** — `manifest-step-gate` blocks S4 from starting unless `phase-{N}-traceability-review.md` exists in the phase directory AND contains `Blocker findings: 0`. A traceability review with unresolved Blockers prevents validation from proceeding.

> **🔒 ENFORCEMENT POINT** — `validation-confirmed-gate` blocks S5 entry until the developer sets `validationConfirmed=true`. This gate fires on `preToolUse` for every build-related tool call during S5.
