*This page documents the telemetry system — what events are recorded, where they are stored, what fields each event carries, and which downstream consumers read the data. It serves the Lead Dev and developers working with telemetry data.*

---

# Telemetry Reference

SAGE records structured event data at three levels: workflow [telemetry](1.3-Glossary) (all hook events during build sessions), PRD interview telemetry (interview-specific events during PRD creation), and kickoff telemetry (events from the completeness check, dev review, and phase-splitter steps that bridge the gap between PRD creation and the build session). All are append-only JSONL files. Neither is written manually — automated systems handle all writes.

---

## Workflow telemetry

### Writers

Two systems write to `workflow-telemetry.jsonl`:

1. The [telemetry-logger](6.2-Enforcement-Reference) hook (`telemetry_logger.py`) fires on every hook event: `preToolUse`, `afterFileEdit`, `beforeShellExecution`, `afterShellExecution`, `afterMCPExecution`, and `stop`. It never blocks. Logging failures do not affect [gate](1.3-Glossary) behaviour.
2. The [phase-splitter](6.4-Skill-Catalogue) skill writes a `session_created` bootstrap event when the session is first created, ensuring the file exists before any hook fires. The [orchestrator](4.0-Build-Phase-Overview) writes TDD spec generation events (`tdd_spec_generation_started`, `tdd_spec_generation_completed`, `tdd_specs_all_complete`) after kick-off and before phase chats open.

### Location

`[SESSION_ROOT]/workflow-telemetry.jsonl`

The session root is resolved from `.sage/sessions/active-session.txt`.

### Common fields (every record)

| Field | Type | Description |
|---|---|---|
| `hook_event_name` | string | The event that triggered the log entry |
| `recorded_at` | ISO 8601 UTC | Timestamp of the event |
| `phase` | string | Phase number (e.g. `"1"`) |
| `step` | string | Current step (e.g. `"build"`, `"code-review"`) |
| `active_agent` | string | Agent name, from `CURSOR_AGENT` environment variable |
| `conversation_id` | string | Cursor conversation identifier |

### Event-specific fields

| Event | Additional fields |
|---|---|
| `preToolUse` | `tool_name`, `tool_input_summary` |
| `afterFileEdit` | `file_path`, `edit_type` |
| `beforeShellExecution` | `command` |
| `afterShellExecution` | `command`, `exit_code`, `stdout_summary` |
| `afterMCPExecution` | `mcp_tool`, `mcp_result_summary` |
| `stop` | `stop_reason` |

### Session lifecycle events

These events are written directly by skills and agents, not by the telemetry-logger hook.

| Event | Writer | When emitted | Key fields |
|---|---|---|---|
| `session_created` | phase-splitter | After session manifest and `active-session.txt` are written | `sessionId`, `featureId`, `mode`, `phaseCount` |
| `tdd_spec_generation_started` | orchestrator | Before generating each phase's TDD spec | `sessionId`, `phaseId`, `phaseLane` |
| `tdd_spec_generation_completed` | orchestrator | After writing each phase's TDD spec | `sessionId`, `phaseId`, `phaseLane`, `scenarioCount`, `tddSpecPath` |
| `tdd_specs_all_complete` | orchestrator | After all phase TDD specs are written | `sessionId`, `phaseCount`, `totalScenarioCount` |

### Hook rejection events

When a blocking [gate](6.2-Enforcement-Reference) rejects a tool call, the telemetry-logger writes an additional `hook_rejection` event. This event carries all common fields plus:

| Field | Type | Description |
|---|---|---|
| `gate` | string | ID of the hook that blocked (e.g. `"validation-confirmed-gate"`) |
| `rejection_reason` | string | The block message sent to stderr |

These rejection events are the primary data source for the [session-performance-evaluator](5.1-SAGE-Hone-Session-Performance) when identifying systematic violations.

## PRD and kickoff telemetry

### Writer

The `prd_telemetry_append.py` utility writes to the PRD telemetry file. This is **not a Cursor hook** — it is a utility function called by skills during execution. It is used by the [prd-interviewer](6.4-Skill-Catalogue) skill during interview execution, and also by the [prd-completeness-check](6.4-Skill-Catalogue), [kickoff-dev-review](6.4-Skill-Catalogue), and [phase-splitter](6.4-Skill-Catalogue) skills during the kick-off sequence.

### Location

Default: `.sage/prd-interview-telemetry.jsonl`

Configurable via `prd.telemetryFile` in `workflow-config.json`.

### Common fields

Every event in this file includes:
- `timestamp` (ISO UTC)
- `event` name
- `workflowKind` — distinguishes the source: `"prd_interview"`, `"completeness_check"`, `"kickoff_dev_review"`, or `"phase_splitter"`
- `linearIssueId`

### PRD interview events (`workflowKind: "prd_interview"`)

| Event | When emitted | Key fields |
|---|---|---|
| `prd_preflight` | After repo preflight check | `preflightOutcome` (`pass`/`fail`), `override` (boolean), `overrideReason` |
| `prd_investigation_manifest` | After codebase reconnaissance | Investigation details (internal) |
| `prd_complexity_classified` | After complexity tier assignment | `tier`, `expectedDuration` |
| `prd_phase_started` | At each interview section boundary | `phaseId` (`P1`–`P9`), `prdRunId` |
| `prd_phase_completed` | At each interview section boundary | `phaseId`, `prdRunId` |
| `prd_interview_completed` | After all interview phases finish | `prdRunId`, `parkedCount` |

Additional common fields for PRD interview events:
- `phaseId`: `preflight` | `P1`–`P9`
- `prdRunId` (UUID, consistent across the entire interview run)

### Completeness check events (`workflowKind: "completeness_check"`)

| Event | When emitted | Key fields |
|---|---|---|
| `completeness_check_started` | Before reading PRD inputs | `prdRunId`, `prdPath` |
| `completeness_check_completed` | After writing assessment report | `prdRunId`, `score`, `passThreshold`, `passed`, `dimensionScores` (`D1`–`D6`), `findingCount`, `linearStatusSet` |

### Kickoff dev review events (`workflowKind: "kickoff_dev_review"`)

| Event | When emitted | Key fields |
|---|---|---|
| `kickoff_dev_review_started` | After transcript fetch, before processing | `transcriptDurationSeconds`, `participantCount` |
| `kickoff_dev_review_completed` | After writing all outputs | `concernCount`, `concernsByCategory` (counts per category), `prdUpdatesApplied`, `reScoreResult` (`score`, `passed`) |

### Phase splitter events (`workflowKind: "phase_splitter"`)

| Event | When emitted | Key fields |
|---|---|---|
| `phase_splitter_started` | Before loading inputs | `mode` |
| `phase_splitter_phases_proposed` | After team confirms breakdown | `phaseCount`, `phases` (array with `phaseId`, `phaseType`, `layer`, `independenceScore`, `effortEstimateHours`) |
| `phase_splitter_completed` | After manifest, Linear issues, and worktrees created | `sessionId`, `phaseCount`, `manifestPath`, `worktreesCreated`, `linearIssuesCreated` |

Note: kickoff events are written to the PRD telemetry file (not `workflow-telemetry.jsonl`) because no session exists yet when these steps run. The `phase_splitter_completed` event marks the boundary — after it fires, the phase-splitter also writes a `session_created` bootstrap event to `workflow-telemetry.jsonl`.

## Downstream consumers

| Consumer | Reads | Purpose |
|---|---|---|
| [session-performance-evaluator](5.1-SAGE-Hone-Session-Performance) | `workflow-telemetry.jsonl`, `.sage/prd-interview-telemetry.jsonl` | Scores agent behaviour, detects systematic violations, verifies kickoff steps ran |
| [intel-recorder](5.3-SAGE-Intel) | `workflow-telemetry.jsonl`, `.sage/prd-interview-telemetry.jsonl` | Calculates delivery metrics (hook rejection rates, step durations, kickoff durations, TDD spec generation duration) |
| [required-references-gate](6.2-Enforcement-Reference) | `workflow-telemetry.jsonl` | Checks for `read_file` events to confirm required references were read |
| [prd-interviewer-effectiveness-evaluator](5.2-SAGE-Hone-Skill-Improvement) | `.sage/prd-interview-telemetry.jsonl` | Evaluates prd-interviewer skill effectiveness |
| [skill-effectiveness-evaluator](5.2-SAGE-Hone-Skill-Improvement) | `workflow-telemetry.jsonl` | Analyses skill execution patterns across cycles |
