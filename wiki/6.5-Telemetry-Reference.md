*This page documents the telemetry system — what events are recorded, where they are stored, what fields each event carries, and which downstream consumers read the data. It serves the Lead Dev and developers working with telemetry data.*

---

# Telemetry Reference

SAGE records structured event data at two levels: workflow [telemetry](1.3-Glossary) (all hook events during build sessions) and PRD interview telemetry (interview-specific events during PRD creation). Both are append-only JSONL files. Neither is written manually — automated systems handle all writes.

---

## Workflow telemetry

### Writer

The [telemetry-logger](6.2-Enforcement-Reference) hook (`telemetry_logger.py`) writes to `workflow-telemetry.jsonl` at the session root. It fires on every hook event: `preToolUse`, `afterFileEdit`, `beforeShellExecution`, `afterShellExecution`, `afterMCPExecution`, and `stop`. It never blocks. Logging failures do not affect [gate](1.3-Glossary) behaviour.

### Location

`[SESSION_ROOT]/workflow-telemetry.jsonl`

The session root is resolved from `.sage/sessions/active-session.txt`.

### Common fields (every record)

| Field | Type | Description |
|---|---|---|
| `hook_event_name` | string | The event that triggered the log entry |
| `recorded_at` | ISO 8601 UTC | Timestamp of the event |
| `phase` | string | Phase number (e.g. `"1"`) |
| `step` | string | Current step (e.g. `"build"`, `"code-review"`) |
| `active_agent` | string | Agent name, from `CURSOR_AGENT` environment variable |
| `conversation_id` | string | Cursor conversation identifier |

### Event-specific fields

| Event | Additional fields |
|---|---|
| `preToolUse` | `tool_name`, `tool_input_summary` |
| `afterFileEdit` | `file_path`, `edit_type` |
| `beforeShellExecution` | `command` |
| `afterShellExecution` | `command`, `exit_code`, `stdout_summary` |
| `afterMCPExecution` | `mcp_tool`, `mcp_result_summary` |
| `stop` | `stop_reason` |

### Hook rejection events

When a blocking [gate](6.2-Enforcement-Reference) rejects a tool call, the telemetry-logger writes an additional `hook_rejection` event. This event carries all common fields plus:

| Field | Type | Description |
|---|---|---|
| `gate` | string | ID of the hook that blocked (e.g. `"validation-confirmed-gate"`) |
| `rejection_reason` | string | The block message sent to stderr |

These rejection events are the primary data source for the [session-performance-evaluator](5.1-SAGE-Hone-Session-Performance) when identifying systematic violations.

## PRD interview telemetry

### Writer

The `prd_telemetry_append.py` utility writes to the PRD telemetry file. This is **not a Cursor hook** — it is a utility function called by the [prd-interviewer](6.4-Skill-Catalogue) skill during interview execution.

### Location

Default: `.sage/prd-interview-telemetry.jsonl`

Configurable via `prd.telemetryFile` in `workflow-config.json`.

### Events

| Event | When emitted | Key fields |
|---|---|---|
| `prd_preflight` | After repo preflight check | `preflightOutcome` (`pass`/`fail`), `override` (boolean), `overrideReason` |
| `prd_investigation_manifest` | After codebase reconnaissance | Investigation details (internal) |
| `prd_complexity_classified` | After complexity tier assignment | `tier`, `expectedDuration` |
| `prd_phase_started` | At each interview section boundary | `phaseId` (`P1`–`P9`), `linearIssueId`, `prdRunId` |
| `prd_phase_completed` | At each interview section boundary | `phaseId`, `linearIssueId`, `prdRunId` |

Every PRD telemetry event includes:
- `timestamp` (ISO UTC)
- `event` name
- `workflowKind`: `"prd_interview"`
- `phaseId`: `preflight` | `P1`–`P9`
- `linearIssueId`
- `prdRunId` (UUID, consistent across the entire interview run)

## Downstream consumers

| Consumer | Reads | Purpose |
|---|---|---|
| [session-performance-evaluator](5.1-SAGE-Hone-Session-Performance) | `workflow-telemetry.jsonl` | Scores agent behaviour, detects systematic violations |
| [intel-recorder](5.3-SAGE-Intel) | `workflow-telemetry.jsonl` | Calculates delivery metrics (hook rejection rates, step durations) |
| [required-references-gate](6.2-Enforcement-Reference) | `workflow-telemetry.jsonl` | Checks for `read_file` events to confirm required references were read |
| [prd-interviewer-effectiveness-evaluator](5.2-SAGE-Hone-Skill-Improvement) | `.sage/prd-interview-telemetry.jsonl` | Evaluates prd-interviewer skill effectiveness |
| [skill-effectiveness-evaluator](5.2-SAGE-Hone-Skill-Improvement) | `workflow-telemetry.jsonl` | Analyses skill execution patterns across cycles |
