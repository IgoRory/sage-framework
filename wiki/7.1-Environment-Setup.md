# Environment Setup

SAGE requires a one-time repository setup by the Lead Dev and per-machine configuration by every developer. This page lists every step, its current status, and what is blocked.

---

## Repository setup (Lead Dev, one-time)

> 🔵 **HUMAN ACTION** — The Lead Dev performs these steps once on the repository. All steps below have been completed on the Profitability repo as of 2026-05-11 unless noted otherwise.

### 1. Create `.sage/` directory structure

Create the following directories and files at the repository root:

```
.sage/
├── sessions/
│   └── active-session.txt
├── skill-update-history.jsonl
├── current-phase.txt
└── workflow-config.json
```

**Status:** Complete.

### 2. Create skill update directories

```
.skill-update-triggers/
.skill-update-staging/
```

**Status:** Complete.

### 3. Copy framework files

Copy hook scripts, agents, skills, rules, templates, and MCP configuration:

| Source (sage-framework) | Destination (Profitability) |
|---|---|
| `hooks-spec/hooks.json` | `.cursor/hooks/hooks.json` |
| `hooks-spec/scripts/*.py` | `.cursor/hooks/scripts/*.py` (14 Python modules) |
| `.cursor/skills/**` | `.cursor/skills/**` |
| `.cursor/agents/*.md` | `.cursor/agents/*.md` (16 agent files) |
| `.cursor/rules/sage-session.mdc`, `phase-context.mdc` | `.cursor/rules/` |
| `.cursor/templates/*` | `.cursor/templates/` |
| `.cursor/mcp.json` | `.cursor/mcp.json` |

**Status:** Complete. 13 Python hook script modules, 16 agent files, 7 skill roots including `sage-intel/`.

### 4. Root `AGENTS.md`

The root `AGENTS.md` serves as the SAGE agent catalogue. Product-specific context lives in `docs/agents-profitability.md`.

**Status:** Complete.

### 5. Update `.gitignore`

Add SAGE entries:

```
.sage/sessions/active-session.txt
.sage/current-phase.txt
manifest.lock
.skill-update-triggers/
```

**Status:** Complete.

### 6. Commit and push

Initial commit with message `init: SAGE framework structure` (or equivalent).

**Status:** Complete (commit `1be3350d`).

### 7. Configure GitHub branch protection on `main`

> 🔵 **HUMAN ACTION** — Requires GitHub admin UI. Cannot be automated.

- Require pull request before merging
- Require 1 approval from Lead Dev
- Require status checks to pass
- Restrict who can push to `main`

**Status:** Manual — requires GitHub admin UI.

## Developer machine setup (all developers)

> 🔵 **HUMAN ACTION** — Every developer performs these steps on their local machine.

### 1. Confirm Python 3.12.x installed

```powershell
python --version
```

Expected: `Python 3.12.x`

**Status:** Complete (Python 3.12.10 confirmed).

### 2. Confirm Node.js v24.x installed

```powershell
node --version
```

Expected: `v24.x.x`

**Status:** Complete (Node v24.13.0 confirmed).

### 3. Install `filelock` Python package

```powershell
pip install filelock
```

Required by the [manifest lock protocol](6.1-Session-Manifest-Reference) for cross-platform file locking during concurrent manifest writes.

> ⚠️ **NOT DONE** — `filelock` is not installed on developer machines.

### 4. Set environment variables

Set the following as **User scope** environment variables (PowerShell):

```powershell
[Environment]::SetEnvironmentVariable("LINEAR_API_KEY", "<your-key>", "User")
[Environment]::SetEnvironmentVariable("NOTION_API_KEY", "<your-key>", "User")
[Environment]::SetEnvironmentVariable("M365_ACCESS_TOKEN", "<your-token>", "User")
```

| Variable | Source |
|---|---|
| `LINEAR_API_KEY` | Linear → Settings → API → Personal API Keys |
| `NOTION_API_KEY` | notion.so/my-integrations |
| `M365_ACCESS_TOKEN` | Microsoft identity platform OAuth (note: expires, needs refresh) |

> ⚠️ **NOT DONE** — All three environment variables are unset on the verification host.

Restart Cursor after setting environment variables.

### 5. Create worktree directory

```powershell
mkdir C:\Sage\worktrees\
```

Used by [phase-splitter](6.4-Skill-Catalogue) in Sprint and Pair modes to create per-phase git [worktrees](1.3-Glossary).

> ⚠️ **NOT DONE** — `C:\Sage\worktrees\` does not exist.

### 6. Connect MCP servers in Cursor

> 🔵 **HUMAN ACTION** — Requires Cursor settings UI.

Connect the following MCP servers:
- **Linear MCP** — `https://mcp.linear.app/mcp`
- **Notion MCP** — `https://mcp.notion.com/mcp`
- **Microsoft 365 MCP** — `https://microsoft365.mcp.claude.com/mcp`

### 7. Clone and pull

Confirm main clone exists. Pull latest `main` with `.sage/` and `.cursor/` directories present.

## Known gaps (verified 2026-05-11)

| Gap | Impact | Resolution |
|---|---|---|
| `filelock` not installed on developer machines | [Manifest lock protocol](6.1-Session-Manifest-Reference) will fail on concurrent writes | `pip install filelock` on all developer machines |
| Environment variables not set (`LINEAR_API_KEY`, `NOTION_API_KEY`, `M365_ACCESS_TOKEN`) | MCP connections will fail; [hooks](6.2-Enforcement-Reference) that call Linear will error | Set variables per Step 4 above, restart Cursor |
| `C:\Sage\worktrees\` not created | [phase-splitter](6.4-Skill-Catalogue) cannot create worktrees in Sprint/Pair modes | `mkdir C:\Sage\worktrees\` |
| All hook scripts present but NOT runtime-validated | 13 [gates](6.2-Enforcement-Reference) have not been exercised in a live Cursor session (Phase 4 of implementation tracker) | Run Phase 4 validation: trigger each gate and confirm correct blocking/passing behaviour |
| No full S1–S8 dry run completed | End-to-end flow unvalidated | Requires a live Cursor agent session on a test branch |
| Linear ↔ GitHub integration blocked | Commit and PR auto-linking do not work | Requires Linear Workspace Admin access (Phase 3, step 3.6) |
| Webhook receiver not deployed | [SAGE Hone](5.2-SAGE-Hone-Skill-Improvement) apply-step pipeline non-functional | Requires Linear Workspace Admin access (Phase 3, step 3.7) |
