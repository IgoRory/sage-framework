# SAGE Hone — Session Performance Evaluation

After every completed work cycle, the [session-performance-evaluator](6.3-Agent-Catalogue) reads the full [session manifest](6.1-Session-Manifest-Reference) and [workflow telemetry](6.5-Telemetry-Reference) to score agent behaviour across five dimensions. The evaluation runs automatically — no human invocation is required.

> 🤖 **AGENT ACTION** — session-performance-evaluator reads `workflow-telemetry.jsonl`, the session manifest, and all phase artifacts. It scores the cycle, writes the performance report, and creates Linear issues for any systematic violations.

---

## Five evaluation dimensions

| Dimension | What is measured | Data source |
|---|---|---|
| **A. Step compliance** | Did agents follow the S1–S8 sequence without attempting to skip steps? | [Telemetry](6.5-Telemetry-Reference) `preToolUse` events, manifest `stepStatus` and `stepTimestamps` |
| **B. Hook discipline** | How many [gate](1.3-Glossary) rejections occurred? Were any systematic? | Telemetry `hook_rejection` events |
| **C. TDD cycle quality** | What proportion of Red-Green-Refactor cycles passed GREEN on the first attempt? | `phase-{N}-tdd-results.md` per phase, telemetry shell execution events |
| **D. Review finding rates** | How many Critical and Major findings appeared at S6 (code review) and S7 (agent testing)? | `phase-{N}-code-review.md`, `phase-{N}-test-results.md` |
| **E. Effort accuracy** | How close were actual phase durations to the estimates in the session manifest? | Manifest `completionLog` entries vs `definition.effortEstimateHours` |

---

## Systematic violations

A **systematic violation** is defined as the same [gate](1.3-Glossary) firing against the same agent more than twice in a single session. A one-off rejection is not a violation — it is normal gate behaviour (the agent attempted an action before its precondition was met, the gate blocked it, and the agent corrected).

When a pattern emerges — three or more rejections of the same gate by the same agent — it indicates a structural problem: the agent's instructions are not aligned with the enforcement layer, or the agent is repeatedly attempting to bypass a constraint.

> 🤖 **AGENT ACTION** — For each systematic violation detected, the evaluator creates a Linear issue with label `violation` and status `Needs Review`, assigned to the Lead Dev.

Each violation issue includes:
- Which [gate](6.2-Enforcement-Reference) fired
- Which agent triggered it
- How many times the rejection occurred
- The relevant session manifest context (step, phase, build mode)

> 🔵 **HUMAN ACTION** — The Lead Dev reviews each violation issue, determines root cause (agent prompt deficiency, missing precondition, or legitimate edge case), and closes the issue with a resolution note.

---

## Performance report

The evaluator writes `performance-report-cycle-[N].md` to the session directory. The report contains:

- Scores per dimension with supporting evidence
- List of all gate rejections with timestamps and context
- TDD first-pass rate as a percentage
- Finding counts from S6 and S7
- Effort variance per phase (actual hours vs estimated range)
- Systematic violations identified (if any)

This report is consumed by the [intel-recorder](5.3-SAGE-Intel) in the next pipeline stage to feed delivery metrics.

---

## Constraints

The session-performance-evaluator operates under strict boundaries:

- Read-only for [telemetry](1.3-Glossary), [manifests](6.1-Session-Manifest-Reference), and skill files — never modifies them
- Writes only to the session directory (performance report) and Linear (violation issues)
- Does not raise violation issues for isolated gate rejections — only patterns meeting the >2 threshold
- Does not fix violations — reports only

---

## Timing in the post-cycle pipeline

The session-performance-evaluator runs first in the post-cycle sequence. The [intel-recorder](5.3-SAGE-Intel) runs after it completes, reading the performance report as one of its inputs.

```
All phases → Build Complete → session-performance-evaluator → intel-recorder
```
