*This page compiles every SAGE-specific term used in the wiki. Each term is defined once here and cross-referenced from the page where it first appears in context. It serves all teams as a lookup reference.*

---

# Glossary

Terms are listed alphabetically. Where a term has a primary page, it is linked.

---

**Agent** — A specialised AI component defined in `agents/[name].md` that owns a specific responsibility within the workflow. Agents execute autonomously within the constraints defined by their agent file and enforced by hook scripts. Distinguished from *skills*, which are interactive and human-facing. See [Agent Catalogue](6.3-Agent-Catalogue).

**Artifact** — A file produced by a step within a phase. Each step produces a named artifact (e.g., `phase-1-implementation-plan.md`). The next step's gate checks for the prior step's artifact before allowing progression. Artifact names follow the pattern `phase-{N}-{artifact-type}.md` (or `.canvas.tsx` for plan previews). See [Build Steps Overview](4.0-Build-Steps-Overview).

**Autonomous mode** — One of two build modes a developer selects at S1. In Autonomous mode, the build agent completes all tasks end-to-end; the developer reviews the finished code at S6 code review. Compare with *Checkpoint mode*. See [S1 — Developer Interview](4.1-S1-Developer-Interview).

**Batch** — In Checkpoint build mode, a logical grouping of implementation tasks that the build agent completes before pausing for developer review. Batches are defined at S2 and follow layer-appropriate boundary rules. See [S5 — Build](4.5-S5-Build).

**Build mode** — The developer's choice of how S5 build execution runs: *Autonomous* (continuous) or *Checkpoint* (paused between batches). Selected during S1 and recorded in the session manifest. See [S1 — Developer Interview](4.1-S1-Developer-Interview).

**Calibration** — Mode-specific datasets (`mob_calibration.json`, `sprint_calibration.json`, etc.) regenerated from the full velocity history after each work cycle. Used by *intel-advisor* for empirical planning. Mob and Sprint data are never blended. See [SAGE Intel](5.3-SAGE-Intel).

**Checkpoint mode** — One of two build modes. In Checkpoint mode, the build agent completes one batch of tasks, runs the batch's tests, writes a summary, then pauses for developer review before starting the next batch. Compare with *Autonomous mode*. See [S5 — Build](4.5-S5-Build).

**Component specification** — A structured companion document to the PRD (stored at `.sage/prds/[FEATURE_ID]/component-spec.md`) that defines UI components: fields, states, interactions, data bindings, and error states. Required by `prd-completeness-check` (dimension D5 scores six elements per component). See [PRD Creation](3.1-PRD-Creation).

**Completion log** — A section of the session manifest appended to as each phase completes. Records actual duration, test status, hook rejections, deferred items, and paths to handoff and completion report documents. See [Session Manifest Reference](6.1-Session-Manifest-Reference).

**Dependent phase** — A phase that has one or more upstream dependencies. Dependent phases may complete S1–S4 (planning steps) while waiting, but their S5 build is blocked by the `foundation-verified-gate` until all Foundation phases have merged and the orchestrator has confirmed regression passes. See [S5 — Build](4.5-S5-Build).

**Feature Walkthrough** — A human-driven meeting where a Product team member walks the team through the PRD details to orient them about what the feature includes. Required for Mob mode (day before kick-off), optional for Sprint mode. Conducted in person or via remote call. See [Sprint Kick-off](3.2-Sprint-Kickoff).

**Foundation phase** — A phase that has no upstream dependencies and has at least one downstream consumer. Foundation phases start immediately at S1 and must complete and merge before Dependent phases can begin their S5 build. See [S5 — Build](4.5-S5-Build).

**Foundation verified** — A session-level flag (`sessionState.foundationVerified`) set by the orchestrator after all Foundation and Independent phases have merged to main and the post-merge regression suite passes. Unlocks the `foundation-verified-gate` for Dependent phases. See [Review, Merge, and Session Close](3.4-Review-Merge-Session-Close).

**Gate** — A condition that must be satisfied before the next step can begin. Gates are enforced by *hook scripts* at the execution layer — not by agent instruction. A gate reads a specific condition (a file exists, a flag is set, a string is present) and either permits or blocks. See [Enforcement Reference](6.2-Enforcement-Reference).

**Hook** — A Python script registered in `hooks/hooks.json` that is invoked by Cursor IDE at specific events (`preToolUse`, `afterFileEdit`, `stop`, etc.). Blocking hooks can prevent tool calls from executing. Non-blocking hooks (telemetry logger, skill update watcher) run alongside other operations. See [Enforcement Reference](6.2-Enforcement-Reference).

**Independent phase** — A phase that has no upstream dependencies and no downstream consumers. Independent phases start immediately and can be built and merged without waiting for or being waited on by other phases. See [S5 — Build](4.5-S5-Build).

**Intel-advisor** — A read-only agent that answers planning questions (weekly scope, release dates, scope changes) using the empirical dataset built by *intel-recorder*. Part of *SAGE Intel*. See [SAGE Intel](5.3-SAGE-Intel).

**Intel-recorder** — A background agent that collects delivery metrics from every completed work cycle, writes to `.sage/intel/velocity-history.jsonl`, regenerates calibration datasets per mode, and optionally updates the Notion metrics dashboard. Part of *SAGE Intel*. See [SAGE Intel](5.3-SAGE-Intel).

**Kick-off** — A structured session that launches a feature's build cycle. Sprint kick-off (75 min) processes developer feedback on a pre-completed PRD, generates the phase breakdown, and initialises the session manifest. Mob kick-off (120 min) includes the PRD interview step with the full team present. See [Sprint Kick-off](3.2-Sprint-Kickoff).

**Linear** — The project management tool used for tracking feature issues, phase issues, skill-update issues, and violation issues. SAGE reads Linear status via MCP to enforce the *phase-approval-gate*. See [Linear Configuration](7.2-Linear-Configuration).

**Manifest** — See *Session manifest*.

**MCP** — Model Context Protocol. The interface through which Cursor agents communicate with external tools (Linear, Notion, Microsoft 365). Configured in `.mcp.json`. See [External Integrations](7.3-External-Integrations).

**Phase** — A unit of work within a session, scoped to a specific set of files (`scopedFiles` in the manifest). Each phase progresses through eight *steps* (S1–S8). In Sprint mode, phases run in parallel across separate worktrees. Phases are classified as *Foundation*, *Independent*, or *Dependent* based on their dependency relationships. See [The Session Lifecycle](2.1-The-Session-Lifecycle).

**Phase type** — The classification of a phase based on its dependencies: *Foundation* (has downstream consumers, no upstream), *Independent* (no upstream, no downstream), or *Dependent* (has upstream dependencies). Assigned by the `phase-splitter` skill at kick-off. See [Sprint Kick-off](3.2-Sprint-Kickoff).

**Planning cycle** — The recurring planning activity where the Product Manager uses *intel-advisor* to determine which features to pull into the next work cycle. Uses empirical data, not human estimation. See [SAGE Intel](5.3-SAGE-Intel).

**PRD** — Product Requirements Document. Authored via the `prd-interviewer` skill and stored at `.sage/prds/[FEATURE_ID]/prd.md`. Must pass `prd-completeness-check` (score ≥ 80/100) before a feature can enter the planning cycle. See [PRD Creation](3.1-PRD-Creation).

**Red-Green-Refactor (RGR)** — The TDD cycle used during S5 build. Red: write a failing test. Green: write the minimum code to pass the test. Refactor: clean up the code while keeping tests green. The `code-simplifier` agent runs automatically after each completed RGR cycle. See [S5 — Build](4.5-S5-Build).

**Required references** — Files listed in `phases[N].definition.requiredReferences` in the session manifest. The `required-references-gate` blocks S5 code writing until every required reference has been read in the current session (confirmed via telemetry). See [S5 — Build](4.5-S5-Build).

**SAGE Hone** — The self-improving subsystem. Observes every session via telemetry, evaluates agent performance after each cycle, and proposes evidence-backed improvements to AI skill instructions for human approval. See [Session Performance Evaluation](5.1-SAGE-Hone-Session-Performance) and [Skill Improvement](5.2-SAGE-Hone-Skill-Improvement).

**SAGE Intel** — The delivery intelligence subsystem. Records empirical delivery data from every completed work cycle, powers planning decisions via mode-specific calibration, and publishes metrics to leadership reporting surfaces. See [SAGE Intel](5.3-SAGE-Intel).

**Scoped files** — The specific files a phase is permitted to modify, listed in `phases[N].definition.scopedFiles` in the session manifest. The code-simplifier agent only touches files within this scope that were edited in the current task. See [Session Manifest Reference](6.1-Session-Manifest-Reference).

**Session** — A single feature delivery cycle from kick-off through to merged, tested code. Tracked by a *session manifest* stored in `.sage/sessions/[session-id]/`. A session contains one or more *phases*. See [The Session Lifecycle](2.1-The-Session-Lifecycle).

**Session manifest** — The single source of truth for a session's state. A Markdown file containing a machine-readable JSON block (parsed by hooks and agents) and a human-readable rendering (for the team). Located at `.sage/sessions/[session-id]/session-manifest.md`. See [Session Manifest Reference](6.1-Session-Manifest-Reference).

**Skill** — A reusable procedure defined in `skills/[name]/SKILL.md` that guides a human-facing, interactive session (e.g., PRD interview, phase splitting, kick-off review). Distinguished from *agents*, which are autonomous executors. Skills may include reference documents in a `references/` subdirectory. See [Skill Catalogue](6.4-Skill-Catalogue).

**Step** — One of eight sequential activities within a phase: S1 Developer Interview, S2 Implementation Plan, S3 Traceability Review, S4 Plan Validation, S5 Build, S6 Code Review, S7 Agent Testing, S8 Completion Report. Each step produces a named *artifact*. Progression is enforced by *gates*. See [Build Steps Overview](4.0-Build-Steps-Overview).

**Systematic violation** — A pattern where the same gate fires against the same agent more than twice in a single session. Detected by the *session performance evaluator* and reported as a Linear issue assigned to the Lead Dev. A single gate rejection is not a violation. See [Session Performance Evaluation](5.1-SAGE-Hone-Session-Performance).

**TDD spec** — A test-driven development specification generated by the orchestrator at kick-off for each phase. Contains Given/When/Then scenarios, edge cases, and scenario-to-test-file mappings. Reviewed by the Product Manager and Lead Dev before the build sprint begins. See [Sprint Kick-off](3.2-Sprint-Kickoff).

**Telemetry** — Structured event records written automatically by the `telemetry-logger` hook to `workflow-telemetry.jsonl` at the session root. Records tool calls, shell commands, MCP executions, file edits, and stop events. Feeds *SAGE Hone* and *SAGE Intel*. See [Telemetry Reference](6.5-Telemetry-Reference).

**Tier** — A dependency level assigned to phases at kick-off. Tier 0 phases start immediately (Foundation and Independent). Tier 1+ phases wait for their upstream dependencies to complete. The merge order follows the tier structure. See [Sprint Kick-off](3.2-Sprint-Kickoff).

**Velocity history** — An append-only JSONL file (`.sage/intel/velocity-history.jsonl`) maintained by *intel-recorder* with one entry per completed phase, tagged with workflow mode. The empirical dataset used by *intel-advisor* for planning. See [SAGE Intel](5.3-SAGE-Intel).

**Workflow mode** — The team configuration under which a session operates: *Mob* (single terminal, full team), *Sprint* (parallel worktrees, distributed), *Pair* (two developers, sequential), or *Solo* (single developer, no kick-off). Selected at the planning cycle. See [Workflow Modes](2.2-Workflow-Modes).

**Work cycle** — A completed session — from kick-off through to all phases merged and post-cycle evaluation complete. The unit of measurement for SAGE Hone evaluation cadence (session performance runs after every cycle; skill evaluation runs every five cycles). See [The Session Lifecycle](2.1-The-Session-Lifecycle).

**Worktree** — A git worktree providing a separate working directory on its own branch, sharing the same repository object store. Used in Sprint mode to give each developer an isolated workspace for their assigned phase. Created by `phase-splitter` at kick-off under `C:\Sage\worktrees\[FEATURE_ID]\`. See [Sprint Kick-off](3.2-Sprint-Kickoff).
