# Session Manifest Reference

The [session manifest](1.3-Glossary) is the single source of truth for session state. Every [hook](1.3-Glossary) reads it to evaluate gate conditions. Every agent reads it to determine what step is active and what work is in scope.

The file has two parts:
1. A **machine-readable JSON block** delimited by ````json ... ``` at the top. This is what all hooks and agents parse.
2. A **human-readable markdown rendering** below the JSON block, regenerated from the JSON on every write. Hooks never parse the markdown — it exists for developers to read at a glance.

---

## Manifest layers

The JSON block contains six layers plus a completion log. Each layer has a defined write owner and immutability rule.

> [**DIAGRAM PLACEHOLDER — Manifest Layer Structure**]
>
> A vertical stack of seven labelled blocks, top to bottom: (1) Header — "written once at kick-off, never modified." (2) Phase Definitions — "immutable after kick-off." (3) Phase Runtime — "updated during build by hooks and agents." (4) Session State — "updated throughout work cycle." (5) Path Validation — "written at kick-off only." (6) Kick-off Outputs — "written during kick-off, never modified." (7) Completion Log — "appended as each phase completes." Left margin labels: layers 1–2 as "IMMUTABLE," layers 3–4 as "MUTABLE," layers 5–6 as "IMMUTABLE," layer 7 as "APPEND-ONLY." Right margin shows write owner for each.

### Layer 1 — Header

Written once at kick-off by [phase-splitter](6.4-Skill-Catalogue). Never modified after creation (except `lastUpdatedAt`, which is updated on every write).

| Field | Type | Description |
|---|---|---|
| `sessionId` | string | Matches Linear feature issue ID (e.g. `LIN-4821`) |
| `featureTitle` | string | Matches Linear feature issue title exactly |
| `featureLinearId` | string | Linear feature issue ID |
| `featurePrdPath` | string | Path to PRD file (`.sage/prds/[FEATURE_ID]/prd.md`) |
| `mode` | enum | `mob` · `sprint` · `pair` · `solo` |
| `prdCompletenessScore` | number | Score from [prd-completeness-check](6.4-Skill-Catalogue) |
| `kickoffDate` | ISO 8601 date | Date of kick-off session |
| `kickoffParticipants` | string[] | Names of all participants |
| `createdAt` | ISO 8601 datetime | Manifest creation timestamp |
| `lastUpdatedAt` | ISO 8601 datetime | Updated on every write |
| `repoRoot` | string | Absolute path to repository root |
| `sessionRoot` | string | Absolute path to session directory |
| `workflowConfigPath` | string | Path to `workflow-config.json` |

---

### Layer 2 — Phase Definitions

One entry per phase. Written at kick-off by phase-splitter. **Immutable** — no agent or hook modifies definitions after kick-off.

| Field | Type | Description |
|---|---|---|
| `objective` | string | Single sentence: what will exist after this phase |
| `phaseType` | enum | `foundation` · `independent` · `dependent` |
| `tier` | number | Execution tier (0 = parallel start, 1+ = sequential) |
| `independenceScore` | number | 0–100, from phase-splitter analysis |
| `effortEstimateHours` | object | `{ low: N, high: N }` |
| `developerProfile` | enum | `ui-heavy` · `backend-heavy` · `full-stack` · `data-only` · `any` |
| `upstreamDependencies` | string[] | Phase IDs this phase depends on |
| `downstreamConsumers` | string[] | Phase IDs that depend on this phase |
| `interfaceContract` | string\|null | What this phase produces for downstream phases |
| `linearIssueId` | string | Linear phase issue ID |
| `worktreeBranch` | string | Git branch name for this phase |
| `worktreePath` | string | Absolute path to this phase's [worktree](1.3-Glossary) |
| `requiredReferences` | string[] | Files agent must read before S5 build |
| `scopedFiles` | object | `{ ui: [], backend: [], data: [], test: [] }` |

Phase type assignment logic:
- **foundation** — no `upstreamDependencies` AND has `downstreamConsumers`
- **independent** — no `upstreamDependencies` AND no `downstreamConsumers`
- **dependent** — has one or more `upstreamDependencies`

---

### Layer 3 — Phase Runtime

Updated during the build by hook scripts and agents. One entry per phase, nested under the same phase key as the definition.

| Field | Type | Writer |
|---|---|---|
| `assignedDeveloper` | string | phase-splitter at kick-off |
| `linearIssueStatus` | enum | Hooks (on Linear status change) |
| `currentStep` | enum | Hook scripts during build |
| `buildMode` | enum | `autonomous` · `checkpoint` |
| `validationConfirmed` | boolean | **Developer only** (manual edit) |
| `startedAt` | ISO datetime\|null | Hook scripts |
| `completedAt` | ISO datetime\|null | Hook scripts |
| `actualDurationHours` | number\|null | Computed at completion |
| `stepStatus` | object | 8 entries (one per S1–S8), each: `pending` · `in-progress` · `complete` · `blocked` |
| `stepTimestamps` | object | 8 entries, each: `{ startedAt, completedAt }` |
| `batches` | array | Checkpoint mode only — batch definitions with `id`, `label`, `taskIds`, `confirmed`, timestamps |
| `currentBatchId` | number\|null | Active batch in Checkpoint mode |
| `findingSummary` | object | Traceability blockers/majors/minors, code review criticals/majors/minors |
| `hookRejectionCount` | number | Incremented by hooks on each rejection |
| `deferredItems` | array | Items deferred during build |

### Layer 4 — Session State

Session-level runtime state updated throughout the work cycle.

| Field | Type | Description |
|---|---|---|
| `status` | enum | `kick-off` · `async-approvals` · `build-sprint` · `review-merge` · `complete` |
| `allPhasesApproved` | boolean | True when all phase issues are Approved |
| `foundationVerified` | boolean | Set by [orchestrator](6.3-Agent-Catalogue) after Foundation merge + regression pass |
| `foundationVerifiedAt` | ISO datetime\|null | Timestamp of verification |
| `foundationRegressionResult` | enum | `pending` · `pass` · `fail` · `not-run` |
| `buildSprintStartedAt` | ISO datetime\|null | When build sprint began |
| `buildSprintCompletedAt` | ISO datetime\|null | When all phases reached Build Complete |
| `integrationTestStatus` | enum | `pending` · `pass` · `fail` · `not-run` |
| `mergeOrder` | string[] | Ordered list of phase IDs for merge sequence |
| `activeLanes` | string[] | Phase IDs currently in progress |
| `completedLanes` | string[] | Phase IDs at Build Complete |
| `blockedLanes` | string[] | Phase IDs blocked on a gate |

---

### Layer 5 — Path Validation

Written by phase-splitter at kick-off after validating all paths in `scopedFiles` and `requiredReferences`.

| Field | Type | Description |
|---|---|---|
| `validatedAt` | ISO datetime | When path validation ran |
| `results` | array | `{ path, status, resolvedAbsolutePath }` per file |
| `missingPaths` | string[] | Paths with status `MISSING` |
| `newPaths` | string[] | Paths with status `NEW` (expected to be created during build) |
| `validationPassed` | boolean | True when no `MISSING` paths exist |

Path statuses: `EXISTS` (file found) · `NEW` (file expected to be created — follows a known pattern) · `MISSING` (file not found, does not match a NEW pattern — **blocks manifest finalisation**).

---

### Layer 6 — Kick-off Outputs

Written during kick-off by [kickoff-dev-review](6.4-Skill-Catalogue) and phase-splitter. Never modified after kick-off.

| Field | Type | Description |
|---|---|---|
| `devReviewLogPath` | string | Path to `kickoff-dev-review-log.md` in session directory |
| `phaseSplitterBriefing` | array | `{ raisedBy, concern, implication, handledAs }` per concern |
| `prdUpdatesApplied` | number | Count of PRD updates made during kick-off |
| `prdScoreAfterUpdate` | number | PRD completeness score after kick-off updates |
| `phaseBreakdownPath` | string | Path to `phase-breakdown.md` |

---

### Layer 7 — Completion Log

Appended to as each phase completes. Read by [session-performance-evaluator](5.1-SAGE-Hone-Session-Performance) and [sprint-coordinator](6.3-Agent-Catalogue).

| Field | Type | Description |
|---|---|---|
| `phaseId` | string | Phase number |
| `completedAt` | ISO datetime | When the phase reached Build Complete |
| `actualDurationHours` | number | Actual elapsed hours |
| `estimatedDurationHours` | object | `{ low, high }` from definition |
| `testsPassing` | boolean | Whether all tests pass at completion |
| `hookRejections` | number | Total gate rejections during this phase |
| `deferredItemCount` | number | Items deferred to future work |
| `handoffDocPath` | string | Path to phase handoff document |
| `completionReportPath` | string | Path to completion report |

## Write ownership table

| Field path | Writer | When |
|---|---|---|
| `header.*` | phase-splitter | Kick-off only |
| `header.lastUpdatedAt` | Any writer | Every write |
| `phases[N].definition.*` | phase-splitter | Kick-off only (immutable) |
| `phases[N].runtime.currentStep` | Hook scripts | During build sprint |
| `phases[N].runtime.stepStatus[step]` | Hook scripts | During build sprint |
| `phases[N].runtime.validationConfirmed` | **Developer (manual)** | S4 review |
| `phases[N].runtime.stepTimestamps` | Hook scripts | During build sprint |
| `phases[N].runtime.findingSummary` | Agents (S3, S6) | During build sprint |
| `phases[N].runtime.hookRejectionCount` | Hook scripts | On each rejection |
| `phases[N].runtime.deferredItems` | Agents | During build sprint |
| `phases[N].runtime.linearIssueStatus` | Hook scripts (afterMCPExecution) | On Linear status change |
| `phases[N].runtime.batches[N].confirmed` | **Developer (manual)** | Checkpoint batch review |
| `sessionState.*` | Hook scripts + orchestrator | Throughout work cycle |
| `sessionState.foundationVerified` | Orchestrator | After Foundation merge + regression |
| `pathValidation.*` | phase-splitter | Kick-off only |
| `kickoffOutputs.*` | kickoff-dev-review + phase-splitter | Kick-off only |
| `completionLog` | S8 stop hook | On each phase completion |

## Manifest lock protocol

Multiple phase lanes may attempt to write to the manifest simultaneously. All manifest writes use a **read-modify-write pattern with a file lock**.

| | |
|---|---|
| Lock file | `manifest.lock` (in session directory) |
| Lock library | `filelock` (cross-platform Python package) |
| Maximum wait | 10 seconds |
| On timeout | `RuntimeError` — another process may be stuck |

The write sequence:
1. Acquire lock on `manifest.lock` (max 10s wait)
2. Read the full JSON block from the manifest file
3. Apply the specific field update
4. Update `header.lastUpdatedAt`
5. Write the full JSON block back
6. Regenerate the human-readable markdown section from the updated JSON
7. Release the lock
